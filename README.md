# Map

A GPUI desktop geospatial viewer with a MapLibre Native vector basemap.

- Run: `devenv shell -- cargo run` (requires Nix and devenv).
- Open raster or vector files as command-line arguments, with the file picker, or by dropping them onto the map; press `?` for keyboard shortcuts.
- Press `Alt+Enter` for the selected dataset’s properties: retained source, spatial, raster-band, and numeric-attribute metadata. `Esc` closes the dialog and returns focus; inspecting properties does not rescan the dataset.
- Press `Ctrl+Alt+O` (`Cmd+Alt+O` on macOS) to search and reopen recent files. The 50 most recently opened files are stored, newest first, as JSON in `$XDG_STATE_HOME/map/recent-files.json` (default `~/.local/state/map/recent-files.json`). Only successfully opened files enter history; reopening a file moves it to the top.
- Rasters without projection information ask for their source EPSG code before opening. The code is remembered with the recent-file entry and reused when reopening the file from any entry point, including after restarting Map. Existing path-only history remains supported. The original raster is not modified; a temporary VRT supplies the missing CRS for display and tile reads. Cancel skips that file without recording it.
- Raster scale/offset metadata is applied in the shader (`physical = stored × scale + offset`), while numeric tile caches retain raw values. For layers declaring scale or offset metadata, the value-range pane shows an **Descale values** checkbox (on by default). Its per-layer setting switches rendering, hover values, and ranges between physical and raw units without reloading tiles; nodata remains excluded. This includes NetCDF `scale_factor`/`add_offset` and GeoTIFF band scaling.
- The **Visualization** pane below **Value range** offers **Extrude pixels** for numeric rasters. Bar heights follow the pixel value within the currently configured color-map range: the minimum stays at ground level, and the maximum reaches the **Maximum height** slider setting (0–200 times the nominal raster pixel width, default 100 at the slider midpoint). The height reference is chosen before coverage or cache coarsening, so changing rendering detail does not enlarge bars. Scale/offset and playback interpolation apply consistently to both height and color. Bar tops keep each pixel’s color, walls use directional shading to reveal their shape, and nodata is omitted; values outside the range use endpoint heights when **Clamp colors** is on and are omitted when it is off. The option starts off, retains per-band styles for static rasters, and applies across frames for animated multiband rasters without reloading raw tiles.
- The icon-only **grid-2x2** toggle beside **Extrude pixels** enables **Average 2×2 pixels**. Each aligned 2×2 block becomes one bar using the mean of its valid values before scale/offset, range normalization, and palette lookup. Nodata does not contribute; all-nodata blocks are omitted, and odd edges use only existing pixels. Heights remain based on the original pixel width. The option defaults off, is disabled while extrusion is off, retains static per-band settings, and applies across playback frames without reloading raw tiles. Flat rendering and raw pixel/hover values are unchanged.
- Toggling **Extrude pixels** grows bars from ground level or collapses them back down over 1 second with cubic ease-out: fast initially, then slowing smoothly into the final height. Rapid toggles reverse from the current height; reduced motion switches immediately. Static rasters and multiband playback share the transition without reloading raw tiles or seeking playback.
- Hold the **right mouse button** and drag horizontally to rotate the map, vertically to tilt it, or diagonally to do both. Tilt is limited to 0–60°. Left-drag pans and scroll zoom preserves the current orientation; fitting a dataset resets to a north-up, untilted view.
- Zooming keeps the displayed raster tiles visible until the replacement zoom grid has finished loading, in both directions. The grids swap without overlapping, preserving opacity and nodata. Animated multiband rasters retain the accepted animation frame while buffering; their existing 256-MiB GPU cache budget is split between the loading grid and retained coverage.
- Every numeric multiband raster whose bands come from one file in band order (GeoTIFF/COG, VRT, other GDAL rasters, and single-variable NetCDF with extra dimensions such as time) shows asset-icon **Play/Pause** and **First/Last** controls and playback-speed presets (1, 2, 3, or 5 bands/sec; default 3) in the bands pane. Temporal interpolation is enabled by default; there is no interpolation toggle. Playback loops, including interpolation from the last band back to the first. Selecting a band pauses and seeks, bringing an offscreen dataset into view; switching datasets or clearing layers stops playback. Multi-variable NetCDF files keep regular per-band controls and styles because their bands come from separate variables.
- Animation batches contiguous windows of up to 20 bands into raw GPU texture arrays and prefetches the following window. Visible tiles share a buffering barrier, so loading freezes animation time instead of skipping ahead. Each endpoint’s scale/offset is applied before value interpolation and color mapping; nodata fades through alpha. The default color range and value-slider bounds use the minimum and maximum across all playback bands in the selected value units, keeping colors consistent and slider handles stable as frames advance. Reset restores this all-band range; palette and clamp policy follow the current band. Reduced motion disables temporal interpolation without preventing explicitly requested playback. Web-Mercator-compatible, band/tile-interleaved COGs are read natively with combined band-range reads: tile-interleaved COGs minimize extra bytes, and distant chunks use bounded read groups to avoid loading whole intervening raster bands. Other sources read each band of a window through the same GDAL warp as static rendering, so they buffer more slowly than native COGs. Cancellation is cooperative between bands, reads, and decodes; an in-progress codec call or GDAL warp cannot be interrupted.
- The title-bar layer selector fits the widest loaded layer name and adapts to font zoom and available window space.
- The background dropdown on the right of the title bar switches between the theme-aware vector map (**Default**), **None**, and tile backgrounds (OpenStreetMap, Google, Esri, Flanders aerial imagery, GRB, Gewestplan, and CartoWeb). It supports keyboard and scroll-wheel selection, like the dataset selector. Changing the background preserves the camera and loaded dataset; regional sources only cover their published bounds. Tile services require internet access and are subject to their providers’ availability and usage terms.
- **OpenStreetMap** uses the [OpenFreeMap Bright vector style](https://tiles.openfreemap.org/styles/bright), with streets and labels rendered by MapLibre Native rather than pre-rendered PNG tiles. No API key is needed. **Default** keeps its existing theme-aware CARTO vector styles.
- The **Color map** dropdown previews each palette. Its **Reverse** checkbox flips the map colors, legend, and dropdown previews without changing the value range or reloading data. The direction is retained independently for each static raster band and vector layer. For animated multiband rasters, palette, reversal, value-range, clamping, and value-unit edits apply dynamically across the layer’s frames without pausing, seeking, or reloading raw tiles. Frame feedback preserves unfinished value-range input instead of replacing it as playback advances. Animated display settings are shared runtime shader parameters, separate from the retained band sources. Range drags reuse the band list, palette samples, tile textures, and error channel rather than rebuilding per-band styles or legends.
- NetCDF files automatically add each georeferenced 2D grid variable to the raster selector. Extra dimensions (such as time or level) become separately selectable bands, labeled with the variable and dimension values, and can be played back; coordinate and scalar variables are not added. Gridded files with a time axis open as rasters even though GDAL also exposes the axis as a vector layer. Files with a variable-level `GeoTransform` attribute are supported without modifying the source file.
- Press `Ctrl+\` (`Cmd+\` on macOS) to cycle appearance through Light, Dark, and Auto (follow system). A brief on-screen indicator shows the selected mode.
- Place custom theme JSON files in the `themes` directory next to map's `config.json`: `~/.config/map/themes/` (or `$XDG_CONFIG_HOME/map/themes/` when set) on Linux, and `~/Library/Application Support/map/themes/` on macOS. Theme files use the [GPUI Kit theme format](https://gpui-kit.com/component/theme), and their light and dark themes appear in **Settings** alongside the bundled ones. New files are picked up when Settings opens; edits to an already loaded theme require a restart. Theme names must be unique: a custom theme with the name of a bundled or earlier-loaded theme is ignored, and a malformed file is logged and skipped.
- GDAL detects vector datasets, including PMTiles and MBTiles, and adds their layers to the selector. Extents and CRS transformations are provided by the `geo` crate’s GDAL API. Vector layers support fit-to-layer and opacity. Layers with numeric properties also show a searchable **Color by** combobox, color-map selection, legend, and editable value range. Integer and floating-point values color points, polygon fills, outlines, and lines; missing, null, and non-numeric values keep the theme’s uniform color. Property, palette, and range choices stay with each layer; changing them does not reload the data or move the camera.
- Vector PMTiles and MBTiles are streamed directly by MapLibre Native: only visible tiles at the appropriate zoom are loaded. GDAL supplies their layer metadata and extents without requesting a feature scan. Raster MBTiles keep their existing raster path. Numeric tiled attributes come from GDAL’s schema; their range defaults to 0–1 (editable) to avoid scanning tiles. Materialized datasets use each property’s finite minimum/maximum, expanding constant-value ranges automatically.
- The full GDAL derivation in `nix-pkgs` enables MBTiles, MVT, and PMTiles support. After publishing changes there, run `devenv update pkgs-mod` and use a refreshed `devenv shell` to pick up the updated package.
- GeoPackage, GeoJSON, shapefile, and other GDAL vector formats are converted to EPSG:4326 (WGS84, longitude/latitude) GeoJSON in the background, preserving feature properties. Conversion uses GDAL’s in-memory filesystem, without temporary files on disk; the resulting shared GeoJSON string is parsed directly by MapLibre. A thin progress bar below the titlebar and a quiet phase label show opening, GDAL conversion, data preparation, and rendering without blocking map navigation. Percentages describe conversion only; preparation and rendering are indeterminate. The indicator stays visible until a matching, settled map frame is applied, rather than disappearing at GDAL’s 100% callback. Every dataset layer is added to the selector. Spatial layers without a declared CRS are rejected rather than guessed; large non-tiled datasets can require substantial memory.
- CSV files with `lat` or `latitude` and `lon`, `long`, or `longitude` columns (case-insensitive) open as point layers. Coordinates are assumed to be WGS84 unless a CRS is declared. GDAL handles quoted fields and delimiter detection; all columns, including the coordinates, remain feature properties. Untyped attribute columns stay strings to preserve identifiers such as `00123`; a `.csvt` sidecar can declare numeric and other field types. Missing or invalid coordinates, ambiguous coordinate headers, and conflicting geometry definitions produce a loading error. Keep a shapefile’s `.prj`, `.dbf`, and other sidecars alongside its `.shp` file.
- Hover a vector feature to inspect its properties in the **Properties** pane at the top left of the map. The pane stays visible while a vector layer is active, even between hits, so its header can always collapse or expand it. Coordinates remain in the lower-left overlay. Native queries only inspect the active layer. Point-only layers use four logical pixels of extra hit tolerance; polygon, line, mixed, and unknown-geometry layers use exact queries to avoid neighboring hits. Raster hover continues to show pixel values.
- Vector basemaps require internet access.


# Development
- Test: `devenv shell -- cargo test --locked` (debug) and `devenv shell -- just test` (release-mode Nextest, also used by CI).
- Test a local NetCDF file: `MAP_TEST_NETCDF=/path/to/file.nc devenv shell -- cargo test --locked netcdf_local_file -- --ignored --nocapture`.
- Package: `just exe` (Windows), `just appimage` (Linux), or `just dmg` (macOS).

## Complexity checks

Run `devenv shell -- just check` after Rust changes, followed by `cargo test --workspace --all-features` and `just test` in the development shell. The devenv `ci:checks` task also runs this gate before building/testing. The individual checks are:

| Command | Check |
| --- | --- |
| `just fmt` | `cargo fmt --all -- --check` |
| `just lint` | Workspace Clippy, all targets/features, `--no-deps`, with the warning/complexity errors required by `AGENTS.md` |
| `just complexity` | `devenv tasks run code:complexity`, using its configured Knots version and thresholds unchanged |

`Cargo.toml` enables `clippy::cognitive_complexity`, `clippy::too_many_lines`, and `clippy::excessive_nesting` at **forbid** level. Their thresholds in `clippy.toml` are **15**, **80**, and **4**, respectively. These are Clippy's own metrics: function length excludes blank/comment-only lines, while nesting includes enclosing inline modules/impl blocks. `forbid` rejects source-level `allow`/`expect` overrides and is compatible with the required command-line `-D` flags. The lint command also denies all warnings and `clippy::type_complexity`, which uses the existing threshold of **200**.

Clippy does not provide cyclomatic complexity. The existing `scripts.knots` command in `devenv.nix` pins **Knots 2.0.0** through `uvx`; `code:complexity` enforces per-function **cognitive ≤ 15**, **McCabe ≤ 10**, **nesting ≤ 4**, and **AIRD ≤ 85**. AIRD is **AI Reasoning Difficulty** (lower is better), not a minimum readiness score. No baseline is currently passed to this task: a clean gate requires zero over-threshold functions. Do not introduce suppressions, broad exclusions, a baseline, or threshold overrides to hide violations.

Knots scans application source under `src/`, including test modules and platform-specific source, without building Rust/native dependencies. It does not traverse `vendor/`, the `infra-rs/` submodule, packaging/tooling scripts, or build output under `target/` and `.devenv/`. Generated `src/bundled_themes.rs` contains only declarations and contributes no functions; no handwritten functions are excluded. Clippy is scoped to this application's workspace, not its dependencies. Source analyzers and Clippy use different metrics, so neither substitutes for the other.

The development shell supplies `uv`/`uvx`. Its first Knots invocation may download the pinned tool; analysis runs locally without uploading source and adds no Rust runtime dependency. For a machine-readable, report-only snapshot, run `devenv shell -- knots -r src/ --format json --completion-report .devenv/knots-completion.json > .devenv/knots-metrics.json`. This exports metrics and scan completeness; always run `just complexity` separately for the configured threshold gate.

## Raster shaders

Flat rendering uses `src/raster_layer.wgsl` and `src/multiband_layer.wgsl`: each tile is a six-vertex quad with fragment-stage color mapping. Extrusion uses the separate `src/raster_extrusion.wgsl` entry points for both static and animated rasters. It draws eight indexed corners per displayed cell (top and four walls, no bottom), culls back faces, and passes a flat premultiplied color from the vertex shader; extrusion fragments do not sample textures. An immutable 30-index buffer is reused across tiles and frames. Extrusion fragments derive face normals from interpolated local positions and apply a fixed northwest light with ambient fill: top colors remain identical to the palette, walls have distinct brightnesses, and alpha is unchanged. This is face shading, not cast shadows; it adds no shadow-map textures or extra render passes. Flat raster rendering is unaffected.

`src/raster_sample.wgsl` and `src/multiband_sample.wgsl` share each renderer's sampling and style rules between its flat and extrusion shader modules. At blend endpoints they sample only the selected snapshot. Raster values remain cached as raw textures; camera, height, range, and playback changes do not require rebuilding a CPU mesh.

Extruded coverage tests the full ground-to-maximum-height volume against the camera frustum, removing rotated offscreen corners without dropping bars whose ground lies outside the viewport. Replacement request detail is independent of cached ancestor heights, so a retained coarse grid cannot keep its replacement permanently coarse. Opaque, non-blended bars and tiles use approximate camera-front-to-back traversal; translucent/fading draws retain their original ordering. Strict extrusion depth tests prevent farther walls overwriting tops when native depth values quantize to the same value.

Extrusion geometry uses distance-based, anisotropic detail reduction. Source cells projecting below half a logical pixel can form aligned power-of-two blocks, bounded to 16 source cells per axis. Each distance-LOD block uses one nearest center sample, or a representative aligned 2×2 valid-pixel mean when the grid-2x2 option is enabled. Distance LOD remains a visual approximation rather than averaging the entire distant footprint or preserving peaks, so very small features may appear only on zooming in. Heights use the source-selected nominal pixel width, before coverage budgets, cached ancestors, DPI, averaging, or geometry strides can change the sampling grid. The shared conversion in `src/raster_extrusion_height.rs` recovers the native projection's actual vertical pixels-per-meter scale from its W row, compensating for MapLibre's use of the orbiting camera-eye latitude rather than the map-center latitude. This prevents height inflation when tilting or rotating global views. CPU frustum bounds and GPU uniforms use the same conversion; normal perspective foreshortening remains. Raw tiles remain full-resolution and cached. Near-plane crossings and invalid projections keep full geometry detail. Flat rendering does not use this planning path.

GPU regressions, including normally ignored device-dependent tests: `cargo test --locked --workspace --all-features extrusion -- --include-ignored --test-threads=1`. Run these serially: a parallel device-test run has intermittently terminated with a native `SIGSEGV`. These check rendering correctness, not a machine-independent frame-time guarantee.

## Console logging

Press `Ctrl+Shift+L` (`Cmd+Shift+L` on macOS) to show or hide the application log panel. It overlays the bottom of the map without resizing or shifting it. It starts hidden, retains the latest 128 KiB of this session's output even while closed, and updates while open. The readonly output can be scrolled, selected, and copied. The panel uses the same filters as console logging, including `RUST_LOG`.

The application uses `log` with `env_logger` and writes timestamped warnings and errors to standard error by default, limited to `map`, `geo`, `inf`, and `tiler`. All other crates, including MapLibre Native, GPUI, and wgpu, are silent by default. Dataset-open failures include the file path and error chain; rendering failures include the selected background.

Set `RUST_LOG` before launching from a terminal to replace the default filter. For example, explicitly enable MapLibre Native's tile, network, and style diagnostics:

```sh
RUST_LOG=warn,map=debug,maplibre_native=debug devenv shell -- cargo run --release
RUST_LOG=warn,map=debug,maplibre_native=debug ./target/release/map 2>map.log
```

Use `RUST_LOG=error` for errors from all crates, `RUST_LOG=off` to disable logs, or `RUST_LOG=map::vector_load=info` for vector-loading timings only. Logs can contain dataset paths and resource URLs; review them before sharing. Windows release builds use the GUI subsystem and do not automatically attach to a parent console; use a debug build from a terminal for console diagnostics there.

## Vector loading diagnostics

Enable `RUST_LOG=map::vector_load=info` when running the application to trace file drop/open, background queueing, GDAL conversion and progress milestones, reopening the converted GeoJSON for bounds, buffer copying, Rust JSON parsing/metadata/cleanup, UI handoff, native parsing/source copying, frame readback, and native idle. Logs include layer/source identities and elapsed times; they do not log feature-property values. A frame's requested source ID is not proof that its geometry is visible.

Set `MAP_TEST_VECTOR` to a local spatial vector file and run these opt-in measurements in release mode:

```sh
RUST_LOG=map::vector_load=info devenv shell -- cargo test --release --locked local_vector_drop_to_display_timings -- --ignored --nocapture
RUST_LOG=map::vector_load=info devenv shell -- cargo test --release --locked local_vector_load_frame_timings -- --ignored --nocapture
```

The first dispatches a real file-drop event through the production view and loader, uses the real renderer worker with a local background-only style, and verifies that the image drawn by headless GPUI contains vector pixels. The deterministic test pumps the frame channel on the test thread, so this is not a measurement of production foreground scheduling or physical monitor presentation. The second isolates native installation, first data-bearing readback, and idle, excluding renderer warmup and network basemap traffic. Neither test asserts a machine-dependent timing threshold.

For the 9,195-feature Statbel statistical-sectors GeoPackage, the 55.4 MB input expanded to 102.5 MB of GeoJSON. One release-mode drop measurement took 5.61 s: 3.05 s GDAL conversion, 0.57 s reopening GeoJSON for bounds, 0.05 s buffer copying, 0.45 s Rust JSON parsing, 0.09 s Rust JSON cleanup/metadata, 0.86 s native installation, and about 0.54 s until a data-bearing frame was drawn. These are local measurements, not general timing guarantees.

On GDAL 3.12.4, that file uses the default Arrow batch conversion path and emits only a terminal 100% progress callback. Production loads now scope `OGR2OGR_USE_ARROW_API=NO` to the conversion thread to obtain per-feature callbacks, restoring the previous thread-local value on success, failure, or unwind. The opt-in Arrow comparison in `src/map_renderer_vector_timing_tests.rs` retains the default path for diagnostics and confirms byte-identical output for this file. This is not a general performance guarantee; drivers without fast feature counts may still provide no intermediate conversion progress.

Progress updates remain coalesced and throttled to avoid a UI event per feature. Conversion completion switches to indeterminate preparation before GeoJSON finalization, extent extraction, and metadata parsing. The rendering phase includes native parsing/source installation and remains visible until native resources, render work, and fades settle and the corresponding image is applied. An idle-only completion republishes the latest shared image, without copying pixels or reading the GPU again. Selection changes, clearing, and errors dismiss the relevant rendering progress; stale source frames cannot finish a newer load.

A release-mode rerun with the phased loader reported conversion milestones at roughly 0.84 s (25%), 1.61 s (50%), 2.27 s (75%), and 2.98 s (100%). Loading finished at 4.17 s, the first data-bearing headless frame appeared at 5.52 s, and the settled frame dismissed progress at 6.22 s. Settlement is deliberately conservative and includes fades/resource work; it does not assert that every dataset must have visible pixels (empty or off-screen datasets can also be ready). The same warm-renderer, local-basemap, and headless scheduling limitations apply.
